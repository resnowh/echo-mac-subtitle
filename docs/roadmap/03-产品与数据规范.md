# 03 产品与数据规范

> v3：Mac 体验与旧数据兼容优先。下文 Archive v2 为未来设计，首期不要求 Mac 改格式；先在 Windows 兼容层读写经验证的 legacy 格式，明确规则见 [07](07-Mac优先的桌面实施方案.md)。

> v2：本页 UI 和路径以桌面为主；移动端采用应用沙盒、分享面板及平台能力显示，见 [05](05-四端产品与架构.md)。首期四端均为用户自填 Key，不增加账户或付费流程。

## 1. 主流程

首次打开 → 填写 Soniox Key → 选择输入及设备 → 使用默认 English → 简体中文或调整语言 → 新建/接续存档 → 开始录音 → 查看实时原文与译文 → 停止并自动保存单段 SRT。

总结为独立可选功能；未填写 DeepSeek Key 不影响字幕。API 配置检查返回可理解的错误，不能仅凭字符串非空就显示服务可用。

## 2. 页面结构

### 主窗口

以字幕阅读为主，建议初始约 1160 × 760 DIP，可缩放。

- 顶部：当前存档、输入方式与设备、开始/停止、连接状态、音量活动。
- 主区：原文/译文成对列表，时间与 Speaker；保持现有双栏阅读方式，窄窗口改为上下排列。
- 存档区：可折叠，包含新建、接续、录音段和导出；不永久挤占字幕空间。
- 总结区：可折叠侧面板，三种范围明确可选；显示生成时间、来源范围及失败重试。
- 底部状态：已录时长、保存状态、音频中断或重连提示。

控件优先采用 WinUI `ListView` 虚拟化、`ComboBox`、`ToggleSwitch`、`InfoBar` 与原生菜单。长字幕列表不要再套外层 ScrollViewer。按 `winui-design` 的布局与可访问性规范设计，具体样式待后续原型验证。

### 紧凑字幕模式（增强）

独立可调整大小和置顶的字幕窗口，显示最近若干条双语字幕，提供回到主窗口、停止与字体大小操作。与主窗口共用会话，打开时不建立第二路识别。默认允许操作；鼠标穿透只作为后续可选能力，不影响恢复窗口控制。

### 设置

服务与密钥、源/目标语言、Speaker、输入设备、外观、字幕字号、导出目录、快捷键、后台行为。展示真实目录和“打开目录”入口。

- 首发保留浅色、深色、跟随系统；增加高对比度验收。
- 密钥掩码显示，保存与删除明确反馈；不进入日志、存档或导出。
- 默认关闭窗口即退出并收尾。只有用户启用后台运行时才最小化到托盘，并持续显示录音状态。
- 原版输入热切换保留；识别模型/语言设置建议下一段生效，或明确提示重建识别段，避免表面已切换但云端仍用旧设置。
- 快捷键可配置、可禁用，冲突须显示；开始/停止不能因键盘焦点变化误触发。

## 3. 交互状态与可访问性

| 状态 | 用户看到 | 可执行动作 |
|---|---|---|
| 无密钥/无可用设备 | 具体缺失项与设置入口 | 修正、刷新设备 |
| 连接中 | 正在连接、音量与缓冲状态 | 取消 |
| 录音中但无声音 | 正在等待声音，显示当前设备 | 切换输入、停止 |
| 阅读历史 | 新增条数提示，保持阅读位置 | 回到最新 |
| 断网/设备失联 | 故障原因、恢复状态、缺失范围 | 重试、切换、停止 |
| 收尾中 | 正在接收最后结果与保存 | 等待；超时给出明确结果 |
| 保存失败 | 失败路径、未保存状态 | 重试、另存 |
| 总结失败 | 保留原文字稿，提示服务问题 | 重试或更换配置 |

支持键盘全流程、合理焦点顺序、读屏标签、100%～200% 缩放和多显示器 DPI 切换。读屏不逐 token 抢读；由用户选择朗读内容。颜色不能成为唯一状态提示。

## 4. 数据契约与迁移

### 新存档建议

采用带 `schemaVersion` 的 UTF-8 JSON，首个新格式标记为版本 2；旧无版本 Swift 格式在兼容层视为 legacy。JSON 便于检查和跨平台传递，首版不引入数据库迁移负担。

| 对象 | 主要字段及语义 |
|---|---|
| Archive | id、title、createdAt、updatedAt、segments、schemaVersion |
| Segment | id、startedAt、updatedAt、输入/识别配置快照、完成状态、entries |
| Entry | id、start/end 相对秒、recordedAt、sourceText、translatedText、sourceLanguage、targetLanguage、speaker、revision |
| Gap | 缺失起止、原因、所属段；用于解释恢复缺口 |
| Summary（可选新存储） | 来源段/条目与修订、范围、文本、生成时间、模型；不混入原文 |

绝对时间统一写 ISO 8601 UTC，UI 按本地时区展示；音频计时用单调时钟。用户改系统时钟不应导致单段字幕时间倒退。

### 旧格式导入规则

1. 保留原文件，并以新文件导入；不就地覆盖。处理成功后给出条目数、段数与告警摘要。
2. `english` → `sourceText`，`chinese` → `translatedText`。不得因旧字段名推断实际语言必然是英文/中文。
3. 旧 `speaker/language/recordedAt` 允许缺失；无语言保持未知，无 recordedAt 使用 segment.startedAt + start。
4. Swift 默认 Date 编码以 2001-01-01 UTC 为参考秒数；导入器明确使用该规则，不按数字大小猜测。必须用原 Swift 编码器生成样本核验，再覆盖跨天/时区用例。
5. 保留 UUID、段顺序和时长；重复导入按 ID 与内容检测，冲突另存副本并提示，不静默覆盖。
6. 未识别的未来版本拒绝改写，提示升级；损坏文件逐文件报告，不能将所有存档显示为空而隐藏错误。
7. 初期支持旧 Mac → 新 Windows 导入。新 v2 → 旧 Mac 不保证可读；Mac 接入共享核心后支持双向交换。若必须在旧 Mac 继续使用，需单独实现 legacy 导出。

### 本地路径与可靠保存

- 逻辑存档位置为当前用户应用数据目录下的 Echo/Archives，由平台层解析；MSIX 与非打包形式的实际路径在打包阶段确认。
- 单段 SRT 默认保存到 Windows 已知“下载”目录，通过系统 API 获取，不拼接用户名；允许用户改目录。
- 临时文件写完并刷新后再原子替换，保留上一份可恢复备份；正常导出失败不影响内部 Archive。
- 已完成字幕建议每 2 秒或达到一定条数做检查点；目标异常退出后丢失的已完成字幕不超过最近一次检查点。实际磁盘异常不作零丢失保证。
- 拆出刚完成录音段会改变两个存档，应先备份，再用可恢复事务记录保证失败后能恢复，不出现段重复或丢失。
- 首版以单写入者运行，避免两个进程同时更新同一 Archive。

## 5. SRT 和总结

单段导出维持原版以第一条有效字幕为基点的规则；全存档按现实时间建立参考线、再保证单调，保留跨段空档。不要悄悄压缩停录时间；紧凑时间线若以后加入，应独立选项。

SRT 使用标准编号、毫秒时间行、原文/译文以及可选 Speaker 前缀；UTF-8 输出。原版整体导出过滤空原文，这在译文单独到达时可能丢内容；新版本建议只过滤原文和译文都为空的条目，并在回归记录中标为有意差异。

总结请求基于快照，记录来源条目及 revision，防止同一范围反复累加。长存档按服务上下文限额分块并汇总，不直接截断尾部；模型、输入规模和覆盖范围可查。继续优先原文，识别不清之处保留不确定性，不覆盖原字幕。模型名称在实现时验证：[DeepSeek 官方模型资料](https://api-docs.deepseek.com/quick_start/pricing)。

## 6. 数据流与安全设计

Soniox 接收采集的音频；DeepSeek 仅在总结开启或手动请求时接收所选文字稿。默认不落盘音频、不把正文和 Key 写进诊断日志；内部短期内存缓冲不等于保存录音。

Windows 使用系统凭据存储或当前用户范围加密保护 API Key，Mac 后续接入使用 Keychain。Archive 默认是本地明文文字稿，应在存储说明中直接注明，不承诺已加密。诊断日志保留错误类型、session ID、时长和队列指标，分享诊断包前预览内容。
