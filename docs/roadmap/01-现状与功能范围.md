# 01 现状与功能范围

> v2 范围说明：本文记录原 Mac 与 Windows 对齐基线。Android/iOS 已纳入总目标，见 [四端方案](05-四端产品与架构.md)；文末旧范围中的“手机端未包含”已由 v2 取代。

## 1. 调研基线

仓库：[resnowh/echo-mac-subtitle](https://github.com/resnowh/echo-mac-subtitle)。本次快照提交：`d16993aea1dedbb9f950e6734b6c9c0badc2508b`。证据保存在 [固定提交源码](https://github.com/resnowh/echo-mac-subtitle/tree/d16993aea1dedbb9f950e6734b6c9c0badc2508b)。

现有工程是 macOS 15+ 的 Swift/SwiftUI 应用。已阅读 README、架构、数据模型、变更记录，以及音频、模型、请求构造、WebSocket、存档、SRT 和 ViewModel 相关源码。以下“已有”指源码存在，未在 Mac 上运行验证。仓库当前没有 Windows 工程；源代码所谓“平台无关”是逻辑边界，不意味着 Swift 文件能直接放入 C# 应用运行。

## 2. 功能对照与首发范围

| 能力 | 当前依据 | Windows 正式版要求 |
|---|---|---|
| 电脑音频、话筒、双输入 | README；Audio；SpeechViewModel | 三种模式全部保留；使用 Windows 音频端点 |
| 录音中热切换输入 | SpeechViewModel；architecture | 字幕和存档不清空；正常切换保持识别会话 |
| 双输入统一格式和混音 | PCM16AudioPipeline | 16 kHz、单声道、PCM s16le；按统一时间线混音 |
| 建连前缓冲 | PCM16AudioPipeline | 有界缓冲，以现有约 2.5 秒为初始配置 |
| 实时双语字幕 | TranscriptViews；SpeechViewModel | 保留历史，区分临时与最终结果，不重复追加 |
| 现实时间、跨天日期、新内容提示 | TranscriptViews | 保留；阅读历史时不强制拉回底部 |
| 自动/指定源语言、严格限制、翻译开关与目标 | TranscriptModels；SonioxRequestBuilder | 全部保留，现有 12 种 UI 语言选项对齐 |
| 匿名 Speaker 与检测语言 | TranscriptModels；token 处理 | 显示、存储、导出；不推断真人身份 |
| 新存档、接续、多录音段、拆出刚结束段 | README；SpeechViewModel | 完整保留；拆段操作具备失败恢复 |
| 自动单段 SRT、整存档导出 | SRTExporter；SpeechViewModel | 时间单调，不直接拼接各段相对时间 |
| 新增内容/当前段/整存档总结 | DeepSeekService；SpeechViewModel | 三种范围均保留；总结不阻塞录音 |
| 浅色/深色/跟随系统、窗口置顶 | EchoMacApp | 原生 Windows 主题与窗口行为，并覆盖高对比度 |
| 睡眠唤醒、设备变化恢复 | MacLifecycleObserver；LifecycleRecoveryState | Windows 等价状态机；用户停止后不得自行恢复 |
| 本地存档、默认不存音频 | TranscriptArchiveStore；README | 保留；密钥改用系统保护的凭据存储 |

## 3. 可沿用与必须重写

- **沿用产品规则和数据语义**：字幕分段、源/目标语言设置、Speaker、分段存档、总结范围、导出规则。
- **移植到共享核心**：PCM 队列/混音逻辑、Soniox 请求与 token 归并、生命周期状态、归档模型、SRT、总结编排。移植后用相同输入与预期结果验证，不承诺逐行复用 Swift。
- **Windows 独立实现**：WASAPI 采集、设备变化、电源通知、凭据、文件路径/保存对话框、窗口/快捷键/主题。
- **Mac 后续接入**：保留 SwiftUI 和原生采集，把协调逻辑逐步换成共享核心，进行双平台回归。

## 4. 源码暴露的设计注意点

1. `SpeechViewModel.swift` 同时协调生命周期、token、保存及总结。重写应按职责分离，避免再次形成大型协调类。
2. 存档字段仍叫 `english/chinese`，但用户可以选择其他语言。新核心使用中性字段名，通过兼容层读取旧字段。
3. `TranscriptArchiveStore` 没有显式日期策略，使用 Swift 默认 Date Codable 语义。跨语言导入必须处理 Apple 参考时间，不能误按 Unix 毫秒解析；需用 Swift 生成样本作最终核验。
4. 原版 Key 保存在 UserDefaults。Windows 不复制这种保存方式，也不从源码底稿读取用户密钥。
5. 原版 DeepSeek 模型名写死为 `deepseek-v4-flash`。本次官方资料提示该旧名涉及别名映射；实现时让模型可配置并验证实际响应，不将模型名视为永久契约。
6. 现有 `ready` 代表客户端已发送配置，不等价于云端已经成功识别。UI 应分开显示连接状态、音频活动与服务错误。

## 5. 范围边界

Windows 增强建议：明确选择播放/录音设备、紧凑字幕窗口、可配置快捷键、可选托盘运行、可修改导出目录。

离线识别、本地大模型、云同步账户、OCR、语音合成、每应用音频隔离和跨会话真人 Speaker 身份未包含在首期。Android/iOS 按 v2 明确纳入；移动端系统音频只覆盖平台实际允许的范围。
