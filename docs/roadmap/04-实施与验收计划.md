## 2. 必须验证的技术关口

- **G1 双平台调用**：C# 与 Swift 都能调用共享核心，取消/退出后不再收到回调，无跨边界内存泄漏。
- **G2 音频时间线**：不同采样率、两路启动错位、缺块、长时漂移均有可解释结果。若目标设备无法稳定捕获，先更新平台适配方案，不跳过问题进入 UI 完成宣告。
- **G3 原版语义对齐**：用已脱敏的服务消息与旧 Archive 样本比较，不仅依据 README 判断兼容。
- **G4 发布可用**：在未安装开发工具的机器完成启动、采集、保存、升级；构建成功不等于安装可用。

## 3. 验收矩阵

| 编号 | 场景 | 验收要求 |
|---|---|---|
| A01 | 电脑、话筒、双输入各连续录音 | 三种模式均能识别、翻译、导出；系统音频不依赖虚拟声卡 |
| A02 | 录音中循环切换输入 20 次 | 无重复 session、文字清空或旧回调污染；中断可见 |
| A03 | 两路 44.1/48 kHz、不同启动时刻 | 目标流时长对应真实时间；不能翻倍；固定信号对齐误差目标 ≤50 ms，未实测 |
| A04 | 长时间双输入 | 60 分钟同步信号漂移目标 ≤100 ms；实际采集时钟不可用时必须说明降级 |
| A05 | 延迟建连与缓冲溢出 | 缓冲内首句保留；超限明确提示缺口；内存有界 |
| A06 | 临时/最终 token、迟到翻译、Speaker 改变 | 无重复句/错配译文；Speaker 与语言保存在 Archive/SRT |
| A07 | 句尾立即停止 | 收到最终结果再保存；超时显示未完整结束而非成功 |
| A08 | 新建/接续/拆段/整档导出 | ID、段数和内容可核对；跨段时间不倒退；失败可恢复 |
| A09 | legacy Archive、缺字段、跨天与时区 | 日期正确、无隐式语言推断；导入原文件哈希不变 |
| A10 | 三种总结与长存档 | 范围正确、增量不重复、覆盖尾部；总结期间录音持续 |
| A11 | 睡眠唤醒 10 次、用户停止后唤醒 | 仅应恢复的会话恢复，另建段；停止后不自启动 |
| A12 | 拔耳机、切默认设备、蓝牙模式变化 | 状态真实；固定设备失联不静默改用其他设备 |
| A13 | 断网、401、配额、服务异常 | 有限重试、可停止、已收文字可保存；缺口明确 |
| A14 | 磁盘满、目录无权限、强退 | 保存失败可见；已成功检查点可恢复；不覆盖好文件 |
| A15 | 深浅/高对比度、多 DPI、键盘/读屏 | 核心操作可达，字幕可读，不仅靠颜色表达状态 |
| A16 | 2 小时长录音 | UI 不冻结、队列不持续增长、保存可恢复；记录资源曲线 |
| A17 | 双平台同样本 | 核心字幕、存档和 SRT 输出一致；平台时间显示差异可解释 |
| A18 | 干净机器安装与升级 | 正常启动、Key 可用、旧档可读、回退不损坏数据 |

音频硬件覆盖内置、USB、蓝牙，以及单/多播放端点；测试环境列明 OS build、CPU、内存、设备、驱动、网络和模型。ARM64 与 Windows 10 未完成独立矩阵前不写入已支持列表。

## 4. 性能目标与测量办法

下列是拟定验收目标，不是当前性能结论。

- 云端延迟：从对应语音结束到 UI 首次显示的 p50/p95，原文与译文分开；先记录 30 分钟固定语料。健康网络下暂以最终原文 p95 ≤3 秒、译文 p95 ≤5 秒为产品目标，P1 根据服务特性校准。
- 本地延迟：收到服务消息到 UI 更新 p95 ≤150 ms。与云端等待分开统计，避免把网络问题误判为界面慢。
- CPU/内存：在记录配置的基准机器连续录音 2 小时；区分音频队列、字幕数据及 UI 缓存。总占用允许随存档内容变化，音频队列和 UI 缓存必须有界。
- 交互：开始/停止即时反馈，实际收尾另显示状态；离线故障不阻塞窗口操作。
- 费用：不猜测小时费用。后续按服务当期价格、实际会话时长与总结 token 使用量建立估算表，并注明来源日期。

## 5. 数据底稿规则

后续每轮测试保留环境、用例、参数、日志指标、结果和失败证据，在数据清单增加条目。真实音频样本仅在用户明确提供用于测试或同意保存时留存；默认应用不保存音频。可优先使用人工合成同步信号与不含个人信息的样例。

## 6. 当前验证状态

已完成：仓库定位；固定提交源码快照；主要功能和数据逻辑审阅；官方平台/服务文档查询与留存；方案文件与本地链接检查。

未完成：Mac 实机运行；Swift 日期样本生成；Windows 音频原型；真实 API 调用；跨语言桥接；性能/硬件/安装测试。以上均为之后实施计划，不能作为已通过结果。
