# Windows A07 停止与最终结果超时验证底稿

日期：2026-09-30  
范围：停止采集 → 发送尾帧/结束标记 → 等待转写服务最终结果 → 保存状态。

## 环境与方法

- Windows 11 build 10.0.26200；.NET SDK 10.0.401。
- 使用 `Echo.CoreChecks --audio` 和本机回环 WebSocket 模拟服务；未打开 Echo 窗口。
- 未提供 API Key，仅使用合成配置与合成识别消息；未连接云服务，未保存音频。

## 检查结果

1. 正常路径：模拟服务先发临时识别，再等待客户端发送结束标记，最后返回最终文本及 `finished: true`。`SpeechSession.StopAsync` 在服务返回最终消息后完成，最终文本已送入转写装配器；对应的整合检查通过。
2. 超时路径：模拟服务读取配置和客户端结束标记后保持连接，但不返回任何最终结果。8 秒期限届满后，`StopAsync` 抛出 `TimeoutException`，信息为“等待服务端返回最后识别结果超时，最后结果可能不完整。”检查确认结束标记已发送且异常明确。
3. UI 停止流程捕获收尾异常，将其转为“最后结果可能不完整”状态，随后仍排空字幕事件队列并尝试保存已有转写内容；该行为由当前实现静态核对，未启动窗口做视觉验证。
4. Release x64 构建通过，0 错误；与核心检查并行构建时共报告 10 条既有 NAudio 弃用警告。
5. 全套 `dotnet run --project windows/Echo.CoreChecks -c Release -- --audio` 共 47 项检查通过；无云端调用、API Key 或音频文件落盘。

## 边界

- 超时固定为 8 秒；真实服务端最终化延迟分布和网络环境仍需实测，以判断该期限是否适合各类会议/课堂场景。
- 本地模拟服务验证协议收尾，不替代真实 Soniox 服务端行为与真实麦克风长时间录音测试。

## 数据留存

仅保留测试代码中的本地模拟消息、断言与本说明。未保存用户语音、设备 ID、API Key 或服务端响应。
